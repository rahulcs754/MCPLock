GitHub Action · CLI · Free and open source

A lockfile for your MCP servers

MCPLock checks .mcp.json, .cursor/mcp.json and .vscode/mcp.json in every PR, blocks risky settings, and fails the check when a server or its tools change without review.

Add to your repo View on GitHub

Why

Configs run code

Open the repo in Claude Code, Cursor or VS Code and every server in the config starts on your laptop, with your keys.

One line is enough

A PR that swaps a package, adds bash -c, or turns on autoApprove looks harmless in review.

Rug pulls

A server can change its tools or hide instructions in a description later. No file in your repo changes.

Safe in CI

MCPLock only starts servers already approved on the base branch. A PR cannot make CI run a new command.

How to use it

  1. Create the lock on your machine and commit it: 
    npx github:rahulcs754/mcplock lock --probe
git add mcp.lock && git commit -m "Add mcp.lock"
  2. Add the workflow .github/workflows/mcplock.yml: 
    on: pull_request
permissions: { contents: read, pull-requests: write }
jobs:
  mcplock:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: rahulcs754/mcplock@main
        with: { probe: false }
  3. Protect the lock with CODEOWNERS: /mcp.lock @your-org/security

How it works

1. Scan

Reads every known MCP config and settings file. Comments and trailing commas are fine.

2. Check rules

Auto-approve, unpinned packages, shell scripts, secrets, plain http.

3. Lock

mcp.lock stores a sha256 of each server config and each tool. Never secret values.

4. Compare

Fails on any drift, and lists every lock change in the PR so a reviewer can approve it.
